# EXPLORE — flyfar v5 / 2026-05-10

**Status**: DONE
**Abstract**: flyfar v5 三 feature 有實作基礎，但 Explorer 發現 7 個 gap：csv.ts 只取首尾 segment 未展開 leg；deepLink 欄位 type 已定義但 JSON output 未確認；--recommend 演算法正確但 table 不支援多 leg 顯示；FlightResult 缺 leg 欄位；multiCityCommand 無 recommend 分支；MultiCityInputSchema 缺 output/recommend/sort 欄位。

---

## Findings

### Finding 1 — csv.ts:18-37 — 多 leg CSV 只呈現首尾 segment
- `flightToCsvRow()` 用 `segments[0]` 和 `segments[last]`，multi-city 多段結果會漏掉中段資訊

### Finding 2 — types.ts:89 + json.ts — deepLink 在 type 但 JSON 輸出未確認
- `SearchResponse` 有 `deepLink?: string`，`search.ts:75` 有 `buildFlightsUrl()` 並注入 `sortedResponse.deepLink`
- `formatJson()` 是裸 `JSON.stringify`，需驗證 stringify 確實包含 deepLink

### Finding 3 — table.ts:135-140 — formatRecommendTable 只取 firstSeg/lastSeg
- --recommend 演算法正確（price 0.4 + duration 0.3 + stops 0.3），但 output 只顯示首末段

### Finding 4 — types.ts:71-79 — FlightResult 缺 leg 欄位
- table.ts 的 legLabel 靠 `returnDate` 推斷，不適用 multi-city

### Finding 5 — search.ts:180-186 — multiCityCommand 無 recommend 分支
- output 只有 csv/json/table，沒有 `--recommend`

### Finding 6 — query.ts:98-106 — buildFlightsUrl 未驗證 URL 格式
- 懷疑：URL pattern 可能不是 Google Travel 接受的格式

### Finding 7 — types.ts:27-36 — MultiCityInputSchema 缺 output/recommend/sort
- 相較 SearchInputSchema 有這些欄位，multi-city CLI 無法使用 --output / --recommend
